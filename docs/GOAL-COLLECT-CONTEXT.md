# Goal 3 — collect missing views and useful context through computer use

Collect the smallest amount of presenter-authorized material that improves the
room reconstruction or makes an object memory more meaningful. Start by inspecting
the approved bundle; ask the quality lane which views are missing. Collect toward
that request, not toward a larger media count.

Read AGENTS.md, services/memory/README.md, export_memory.py and assemble_capsule.py.
Start in a separate `work/selected-context-<name>` worktree from `fd88405` or a
verified descendant of `origin/integration/one-chapter`. Own `services/memory/`
and ignored capture artifacts. Preserve the other lanes' code and contracts.
This is the low-touch teammate lane: let Codex handle packaging and validation;
the teammate supplies source selection and checks proposed interpretations.

The partner's approved Austin bundle is on `codex/tito-whatsapp-handoff`, last
verified at `4c3b145`, under `services/memory/bundles/austin-trip/`. Fetch current
GitHub state first, read its README and verify asset hashes. The coordinator's
ignored local copy is `artifacts/partner/austin-trip-4c3b145/`. Do not repeat an
already completed export or seek screenshots that are already supplied.

Two useful outputs:

- **Reconstruction material:** original-resolution same-room photos or clips
  adding unseen sides of the table, wall details, door and floor, preferably with
  fewer moving subjects. Keep capture sequences grouped. Record dimensions,
  duration, blur/occlusion and viewpoint contribution. A timestamp or matching
  group alone does not prove the same room configuration. Do not mix soccer
  footage into the room reconstruction. Send accepted files and their source
  locators privately to the quality lane for registration assessment.
- **Memory context:** selected captions, adjacent messages, dates and presenter
  interpretation that explain an existing object-linked photo/video. Keep source
  dates separate from export time. Preserve conflicting evidence. Distinguish a
  planned event, a caption's claim and an observed outcome.

Use actual computer use in the already authorized selected source app/item. Check
foreground ownership with the companion before native interaction; one session
controls the foreground at a time. Work on the existing local bundle while UI
ownership is unavailable. Scope browsing to the selected trip/group and candidate
room media. Do not enumerate the full camera roll, unrelated chats or accounts.
Do not send messages, contact participants, modify source records or publish media.
Ask for a specific source locator only when it is missing and independent work is
exhausted. Do not interpret another agent's inactivity as UI ownership permission.

Read the source UI, save original selected files where available, and retain an
actual source screenshot plus locator and observation timestamp. A capture claim
requires real evidence; if a screenshot cannot be captured, retain conservative
manual provenance and state the gap. Do not fabricate screenshots or infer faces.
Use existing exporters and assembler; no new crawler, account system or database.

First pass budget: 20 minutes, up to five promising clips or 30 relevant gallery
items before reporting whether useful new coverage exists. Stop early if the
needed material is already in the bundle. If the available source cannot supply
missing viewpoints, provide a concrete recapture request: a slow overlapping pass
around the actual objects in good light, with the objects stationary and originals
retained. Sending that request to other people still requires explicit permission.

Finish by handing off a deduplicated manifest of selected files with hashes,
source/evidence, content-versus-reconstruction purpose, and the gap each file fills.
The quality lane must consume at least one accepted candidate or explicitly reject
it with a capture reason. Assemble three to five improved cards, preserving real
provenance, and verify their media/source display in the live viewer. Coordinate
object bindings with the feature lane; do not assign arbitrary XYZ points yourself.
No new data found is a valid collection finding, not proof that room quality improved.
Push only verified code and non-private handoff documentation.
